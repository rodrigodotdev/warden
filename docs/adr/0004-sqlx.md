# ADR-0004 — SQLx as the driver toolkit

**Status:** Accepted · 2026-08-19

## Context

Warden needs asynchronous MySQL and PostgreSQL support, pooling, prepared-statement
bind arguments, TLS, row streaming, and a native Rust ecosystem without C client
libraries.

Compile-time macros such as `query!` are not decisive because agent SQL arrives at
runtime.

## Decision

Use SQLx 0.9.x with `default-features = false`. See `docs/operations.md` section 2.2
for the exact feature set and the rationale for each exclusion.

## Consequences

Agent queries use runtime APIs with bind parameters. Internal static SQL may use
macros when they improve correctness without complicating CI.

SQLx defaults (`any`, `macros`, and `migrate`) must remain explicitly disabled on the
`sqlx` facade. Two contradict project decisions, and disabling them turns the rules
into compile-time errors: `sqlx::AnyPool` and `sqlx::migrate!` do not exist in this
build.

**Accepted upstream limitation, recorded 2026-08-24 (Milestone 6).** Disabling them
on the facade does not stop the code from compiling. `sqlx` 0.9.0 declares
`sqlx-core = { version = "=0.9.0", features = ["migrate"] }` unconditionally and takes
its default features, which include `any`, so `sqlx-core`'s migration and
driver-agnostic modules are built regardless of Warden's feature selection. Warden
accepts that rather than replacing the facade with direct `sqlx-core`, `sqlx-mysql`
and `sqlx-postgres` dependencies, which would be a larger architectural change than
the surface it removes. What the decision above still guarantees is what matters: no
migration or `Any` **API** is reachable from Warden's code. `tests/architecture.rs`
asserts both halves — the facade features are off, and `sqlx-core` still compiles
those two modules — so the day upstream changes it, this ADR is revisited rather than
silently outdated.
